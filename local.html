本地部署

ON-DEVICE · ENGINE · QUANTIZATION

本地部署解决的是数据不出门、断网可用、长期成本可控，代价是模型上限与维护成本。 能不能跑看显存，跑得快不快看带宽，跑得稳不稳看量化与上下文设置。

结论先行 / VERDICT

  1. 先定显存，再选模型。模型大小不是按「哪个更强」选，而是按「权重 + KV + 框架开销」能不能塞进显存选。
  2. 量化是必选项，不是妥协。8 位几乎无损；4 位在通用任务上够用，长链推理要单独测。
  3. 统一内存与独显是两条路线。前者装得下大模型但 decode 慢，后者快但显存小。选路线等于选你能接受的任务类型。
01

推理栈怎么选

按用途分，不要混用。同一个机器上装两套是常态。

工具面向平台适合注意
llama.cpp / GGUFCPU + GPU 混合全平台单机跑量化模型，CPU/统一内存也能用参数多，性能调优靠经验
Ollama开箱即用全平台快速试模型、本地 API底层是 llama.cpp，细节可调项少
LM Studio图形界面桌面不写代码时试用、对比模型批量与自动化能力弱
vLLM服务端吞吐NVIDIA / ROCm多并发 API、PagedAttention显存要求高，部署更重
SGLang结构化生成NVIDIA / ROCm高吞吐、复杂提示与约束解码生态比 vLLM 小
MLXApple 芯片macOSM 系列统一内存优化跨平台性差
ComfyUI图像 / 视频生成全平台节点式扩散工作流显存峰值高，需要单独调

03

硬件路线

Apple 统一内存 macOS

带宽 500–800 GB/s，能装大模型，功耗低、安静。适合单用户长文与创作。

x86 统一内存 Strix Halo

128 GB 容量、约 256 GB/s 带宽。装得下，decode 偏慢；图像生成反而更吃容量。

单卡独显 RTX

带宽 1–1.8 TB/s，decode 快。显存 24–96 GB，决定模型上限。

多卡 / 服务器 Datacenter

显存与带宽都能堆，但互联、功耗、噪音与成本进入另一个量级。

04

常见坑

只看权重体积没算 KV Cache，长上下文一到就 OOM。
上下文开太大并发数骤降，吞吐反而更差。
驱动与运行时版本不匹配ROCm / CUDA 与框架版本必须对齐。
把 mmap 当万能内存映射能省加载时间，但首次推理仍要读盘。
量化格式要配套GGUF 给 llama.cpp，AWQ/GPTQ 给 GPU 服务端，不能混装。
先跑基线再调优先确认官方示例能跑通，再动参数。
05

本机实践

当前实例跑在一台 Ryzen AI MAX+ 395（Radeon 8060S 统一内存）上，物理内存 64 GB， Windows + ROCm 环境，串行出图。它不是「最合适的本地推理机」，但能把大模型完整放进内存， 适合做容量换速度的实验。
