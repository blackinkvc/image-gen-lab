latent 放大链

NEAREST-EXACT → REFINE 26 → 4X-ULTRASHARP → LANCZOS

唯一真正抬高细节密度的路径。它不是「把图放大」，而是在放大后的潜空间里重新采样一遍， 所以中高频都有新信息。代价是单张 6 分钟级，而且会把原图的瑕疵一起放大。

结论先行 / VERDICT

  1. 它是唯一能真提细节密度的链路。refine 发生在放大后的潜空间，有新的像素预算承载细节；这与双采只碰最后 20% 有本质区别。
  2. 单张 6 分钟级，只适合主视觉。三个 seed 终图为 160.2 / 355.0 / 380.9 s，其中两例峰值 21.5–21.8 GB，属于「一次跑一张」。
  3. 它会放大瑕疵。飘动布料出拖影、袖口飘片——放大后低 denoise 不足以重建布料边界，这组组合已被弃用。
01

它是什么

一条五段式管线：先在 1024×1536 出原图，在潜空间用 nearest-exact 放大到 1536×2304，然后在放大后的潜空间里再跑 26 步 refine，接着过 4x-UltraSharp 放大到 6144×9216，最后用 lanczos 落到交付尺寸 4096×6144。

关键不在放大算法，而在中间那次 refine。只做插值放大，细节密度不会增加，只是把已有的像素摊开； 在放大后的潜空间里重采样，模型才有空间去「补」中频与高频内容。这是它和 双采最本质的区别。

原图段与 refine 段用不同 seed（refine 用 seed+1），cfg 从 5.5 降到 5.2，避免放大后过饱和。 终图再由 PIL 做上下各 8% 的渐变压黑，不加文字，留作海报版式空间。

怎么跑

NODE GRAPH8K 海报 / 五段链

VAEDecode → SaveImage   # 原图落盘（_raw）

                        width=1536 height=2304
KSampler                steps=26 cfg=5.2 denoise=0.45
                        seed=原 seed + 1

UpscaleModelLoader      4x-UltraSharp.pth   # → 6144 × 9216
ImageScale              method=lanczos  width=4096 height=6144
VAEDecode → SaveImage
# post（PIL）：上下各 8% 渐变压黑，无文字

显存峰值出现在 4x-UltraSharp 之后的解码段，不在采样段。所以这条链的瓶颈是像素数， 不是步数——再加步数不会更难跑，再加尺寸会。

05

判定

细节密度 ✓放大后的潜空间有新预算，蕾丝、锈斑、孢子颗粒都有新信息，不是插值摊开。
主体结构 ✓低 denoise 锁结构，头盔轮廓与裂纹走向不变。
可用性 ✓三个 seed 全部落盘 4096×6144，可作海报底图。
飘动布料 ✗裙摆、袖口出拖影——放大后 d0.45 不足以重建布料边界。
单张成本 ✗终图 160–381 s，只能一张一张来。
会放大瑕疵 ✗原图的接缝错误、多余线条会被一起锐化。
适用面 ✓静物、金属、硬表面表现最好；复杂动态布料最差。
批量 ✗不适合 ≥20 张的补图队列，成本不可接受。
06

优缺点

KEEP

  • 唯一真正提升细节密度的路径，中高频都有新信息。
  • 原图段可复用，终图失败不必从零重跑。
  • 静物、金属、硬表面效果稳定，三个 seed 都可用。
  • 输出尺寸可控，lanczos 收口能精确落到交付规格。

DROP

  • 单张 3–6 分钟，不能进批量队列。
  • 飘动布料出拖影，相关组合已弃用。
  • 原图瑕疵会被放大，不能用来救废图。
  • 显存随像素数增长，再加尺寸就危险。
07

没验证的 / 数据限制

  • 只在 SDXL 上跑过：Z-Image + 4x-UltraSharp 的组合没有数据，不能按比例推断耗时。
  • 拖影组合没有逐组参数：裙摆拖影、袖口飘片的现象有记录，但当时没留下完整的参数与图，无法复现对照。
  • 512904683 数据异常：160.2 s 与 3.33 GB 都偏离同链路两例，原因未定位，不取平均。
  • refine 步数未扫描：26 步是既定值，没做 20 / 32 步对照；d0.25 的细节衰减只有推断。
  • 4x-UltraSharp 无替代对照：没有和其他放大模型（如 ESRGAN 系列）比过。
