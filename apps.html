应用地图

按「用户拿到的最终形态」分类，而不是按底层模型分类：

通用助手 Chat

一个输入框接住所有需求。壁垒在分发渠道与记忆，不在模型本身。

编码 IDE / CLI

最成熟的一类。有测试与版本控制当判卷人，Agent 能自我纠错。

图像 / 视频 Media

从「生成一张图」转向「可控地改一段素材」，工作流比单张质量更重要。

音频 Voice / Music

语音合成已接近可用，音乐生成在版权与可控性上仍在磨合。

搜索 / 研究 Research

从给链接变成给结论，引用与可核查性是核心差异。

办公 Workspace

嵌进文档、表格、会议里，靠既有分发获取用户。

03

形态变化

过去三年，应用层发生了四次位移，每一次都改变竞争壁垒：

聊天框 → 工作流单轮问答变成多步执行，产品开始管理状态与权限。
通用 → 垂直通用助手的边际优势下降，行业知识与数据接入变成壁垒。
按订阅 → 按结果从「每月多少条」转向「完成多少任务」，计价单位在变。
云端 → 端侧手机与 PC 开始跑小模型，隐私与延迟是主要卖点。

一个判断方法：如果产品价值主要来自「模型更强」，它迟早会被下一版基模吸收；如果价值来自工作流、数据与分发，才有独立空间。

04

选型：先问四个问题

  • 任务能不能验证？能自动判卷的场景（代码、结构化数据）最适合交给 AI。
  • 错了谁负责？高风险决策必须保留人工复核，产品要有可追溯记录。
  • 数据能不能出去？决定用云端 API 还是本地部署，直接影响可用模型范围。
  • 成本按什么算？按座位、按 token、按任务，三种计费对应完全不同的用量曲线。
