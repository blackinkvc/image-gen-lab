01

它是什么

Juggernaut-XL v9 是 SDXL 1.0 的社区微调版，目标是「3D 半写实照片感」。潜空间 4 通道， 意味着整套 SDXL 生态都能直接用：IPAdapter、ControlNet、LoRA、各种 refiner。

在本机的分工里，它承担两件事：用 IPAdapter 把服装版型和配色锚到参考图， 以及用 OpenPose ControlNet 改姿势。这两项是它相对 Z-Image 唯一的优势区。

代价在材质：皮肤高光收得太紧，织物缺少漫反射层次，近距离看有明确的塑料感—— 这就是「更锐但更蜡」的来源。高频锐度是够的，但锐的是边缘，不是质感。

02

怎么跑

日常出图走配方 A；要换姿势才上配方 B。两套都基于 i2i。

NODE GRAPH配方 A / 锁形体 + 锁画风
CheckpointLoaderSimple  Juggernaut-XL_v9_RunDiffusionPhoto_v2
LoadImage               [项目基准立绘]
VAEEncode               denoise=0.45
IPAdapterUnifiedLoader  preset=PLUS (high strength)
IPAdapterAdvanced       weight=0.85  weight_type=linear
CLIPTextEncode          positive / negative
KSampler                steps=24 cfg=5.0 sampler=dpmpp_2m
                        scheduler=karras denoise=0.45
VAEDecode → SaveImage

# 配方 B / 换姿势：denoise 提到 0.62，IPAdapter 权重降到 0.55
# weight_type=style transfer，并接 ControlNet openpose（strength 1.0）
  • 配方 A —— i2i d0.45 + IPAdapter 0.85 linear。服装版型、配色、义体位置跟参考图走。
  • 配方 B —— i2i d0.62 + IPAdapter 0.55 style transfer + OpenPose。姿势跟骨架走。
  • 采样 —— dpmpp_2m / karras，24 步 cfg 5.0 已稳定，再加步数收益很小。

关键结论：d0.45 时 ControlNet 拉不动姿势。想改姿势必须同时把 denoise 提到 0.62 并接受服装细节漂移，两者不能兼得。

05

判定

按 2026-11-09 起的口径：只核对服装版型、配色材质、配饰、发型轮廓、体型，不看脸。

服装版型 ✓IPAdapter 0.85 能把甲片分块、腰线与裙摆层次锚住，d0.45 时最稳。
配色 ✓主色与点缀色跟随参考图，紫色胸线发光位置稳定。
材质 ✗皮肤与织物偏蜡、偏塑料；这是被替换的主因。
配饰 ✓机械前臂、腰侧挂件在 i2i 下保持良好。
姿势控制 △d0.45 时 ControlNet 无效；d0.62 才能拉动，但服装开始漂。
体型比例 ✓九头身与四肢长度稳定，少见断肢。
速度 ✗中位 32 s、8K 原图 60–90 s，落后 Z-Image 一档。
生态迁移 ✗4 通道潜空间，权重与 LoRA 都无法迁移到 Z-Image。
06

优缺点

KEEP

  • 唯一有 IPAdapter + ControlNet 的组合，版型与姿势控制最完整。
  • 峰值显存低（A/B 批最低 11.0 GB），能和别的进程共存。
  • 生态成熟，调试手段多，出问题容易定位。
  • 做对照基线时，它的锐度能反衬 Z-Image 的高频上限。

DROP

  • 材质蜡、塑料感明确，近距离不可交付。
  • 24 步起步，单张成本约为 Z-Image 的 1.5 倍。
  • 4 通道潜空间，跟 Z-Image 的 16 通道完全不互通。
  • 姿势与版型只能二选一，d0.45 与 d0.62 之间没有中间解。
07

没验证的 / 数据限制

  • 步数扫描没做：台账全部 24 步、A/B 全部 30 步、8K 原图 34 步，三套配置之间没有逐步对照，不能说哪一套最优。
  • cfg 只跑到 6.0：没有 7.0 以上的记录，高 cfg 的过饱和边界未测。
  • refiner 未接：SDXL base → refiner 的跨模型精修没有做过对照。
  • 8K 链只在 SDXL 上跑过：Z-Image + 4x-UltraSharp 的组合没有数据，不能推断。
  • A/B 只有一组入站：批次共 5 个主体，因收录边界只公开玄枢 003 这一组。
